# Collection

1. **Root.** The working directory, after `-C`, which must hold a `fac.py`: one holding none fails at once, naming the nearest ancestor that does. Facere never searches for a root, so a subdirectory holding its own `fac.py` runs as a project of its own, with its own graph and output directory, and a project meant to be built whole is run from its top, which `-C` reaches from anywhere. One graph per project avoids the partial graphs Peter Miller's "Recursive Make Considered Harmful" describes.
2. **Find.** The root's `fac.py` loads first, then every other `fac.py` under the root outside hidden directories, the output directory, and the globs the root passed to `fac.exclude(*patterns)`, found by walking the tree. `fac.exclude` keeps out a vendored dependency that ships a `fac.py` of its own, or a `node_modules` tree, whose directories the walk then never enters. It affects collection only, so `fac.sources` can still list an excluded directory's files, and a project can build vendored sources while keeping their own build out of its graph. The state caches each directory's listing against its mtime, which changes whenever an entry is added or removed, so an unchanged directory costs one stat, and one modified too close to the last invocation for its mtime to be trusted is listed again, as a racy file is hashed again. Facere depends on no version control system.
3. **Load.** Each `fac.py` runs once as a script under a private name, so none is importable, and a directory named like a standard-library package, such as `test/`, collides with nothing. Shared modules, shipped extensions included, are imported afresh on every invocation, and every rule and task joins a graph owned by the current invocation, so `fac.main()` can run repeatedly in one process and tests can assemble graphs in isolation. During collection, Facere points `sys.pycache_prefix` at `.fac/pycache/` in the output directory, so importing a shared module or the project's own package writes no `__pycache__/` under the root, where a glob such as `fac.sources("pkg/**")` would list it and re-execute its consumers after each Python upgrade. Each invocation first recompiles the bytecode cached there for modules under the root, outside hidden directories, where a virtual environment lives, into files Python validates by a hash of the source, and keeps those as they are: Python trusts its default bytecode on a source that kept its size and whole-second mtime, so a same-size edit within that second would run the old code. Under `--check-hash-based-pycs never`, which trusts even those, it deletes them instead. Collection imports only the standard library, Facere, and modules under the root, and a shared module that the standard library or an installed package shadows, resolving to a different file, fails, so a project's own package installed in editable mode passes.
4. **Define.** Decorating a function defines its rules or task, so every rule and task exists once the files have loaded. Overrides then adjust the rules under their directories, and `fac.rules` placeholders are filled.
5. **Validate.** Outputs are compared without case, so Windows and macOS agree with Linux. An output inside another rule's directory output is a conflict, since a directory output owns everything in it. A rule's input holding the output directory, such as `.`, fails, since its content changes on every build, while `fac.sources("**")` lists the project's files without it. A path both listed by `fac.sources` and output by a rule suggests filtering it out of the list, since `fac.sources` takes no exclusions: a project filters the list in Python. Virtual outputs are compared by store and key, and conflict as [stores](./stores.md#validation) lists. A cycle among rules, through paths or virtual outputs, prints as the full loop. For a rule a helper defined, the line named is the call in the `fac.py`, not the decorator inside the helper's extension.

Facere reports every collection error it finds, not just the first, with one `note:` line per further party, as gcc does, so Vim's default `errorformat`, Emacs's compilation mode, and a VS Code problem matcher reach every one.
